# ADR-0001. `Dice.__deepcopy__` падает с `DiceCopyError`, а не возвращает тот же объект

**Статус:** принято

## Контекст

`Dice` — иммутабельный value object (`frozen`, `slots`), но его стратегии могут хранить состояние.
Например, у `SeededRandomStrategy` внутри свой `random.Random`. Поэтому `copy.deepcopy(die)`
копирует и стратегии: копия должна бросаться независимо от оригинала.

Раньше при любой ошибке копирования стратегии метод молча возвращал `self`:

```python
try:
    ...
    return replace(self, ...)
except Exception:
    return self
```

Это нарушало сразу три принципа:

- **Контракт метода.** `deepcopy` обещает независимый объект, а возвращал тот же самый. Вызывающий код
  не может отличить настоящую копию от подмены.
- **POLS (принцип наименьшего удивления).** «Копия» и оригинал делили одну стратегию. Два кубика,
  которые выглядят независимыми, расходовали один генератор, и воспроизводимость seed ломалась
  в непредсказуемом месте, далеко от причины.
- **Fail fast, fail loud.** Ошибка не исчезала, а превращалась в тихий логический баг.
  `except Exception` к тому же ловил всё подряд, включая ошибки в коде самой стратегии.

## Решение

- Ошибка копирования стратегии поднимает доменное исключение `DiceCopyError`.
- Оно наследует `TypeError`, потому что `deepcopy` несовместимого объекта сам обычно бросает
  `TypeError`. Код, который уже ловит `TypeError`, продолжит работать.
- Исходная ошибка сохраняется через `raise ... from error` и доступна в `__cause__`.
- Текст ошибки называет кубик, который не удалось скопировать.
- `try` охватывает только копирование стратегий, а `replace(...)` вынесен из него, чтобы не перехватывать
  посторонние ошибки.

## Рассмотренные варианты

- **Оставить тихий возврат `self`.** Отклонено по причинам выше.
- **Просто убрать `try` и пробросить исходную ошибку.** Тоже fail loud и проще. Но пользователь
  библиотеки получил бы разнородные исключения из чужого кода стратегии, без указания, какой кубик
  виноват, и без одной точки для `except`. Доменное исключение даёт одну точку для `except`
  и контекст, а исходная ошибка не теряется благодаря `from`.

## Последствия

- Стратегия, которую нельзя скопировать (например, с блокировкой или открытым ресурсом внутри),
  теперь заметна сразу при `deepcopy`, а не через странные броски позже.
- Появилось новое публичное исключение `dicing.DiceCopyError`.
- Поведение покрыто регрессионными тестами в `tests/test_operators.py`: копия независима, а
  ошибка копирования поднимает `DiceCopyError` с исходной причиной.
