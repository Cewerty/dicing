# ADR 0001: `Dice.__deepcopy__` падает с `DiceCopyError`, а не возвращает тот же объект

## Статус: Accepted

## Контекст

`Dice` — иммутабельный value object (`frozen`, `slots`), но его стратегии могут хранить состояние.
Например, у `SeededRandomStrategy` внутри свой `random.Random`. Поэтому `copy.deepcopy(die)`
копирует и стратегии: копия должна бросаться независимо от оригинала.

Раньше при любой ошибке копирования стратегии метод молча возвращал `self`:

```python
try:
    ...
    return replace(self, ...)
except Exception:
    return self
```

Это нарушало три принципа:

* **Контракт метода.** `deepcopy` обещает независимый объект, а возвращал тот же самый. Вызывающий код
  не может отличить настоящую копию от подмены.
* **POLS (принцип наименьшего удивления).** «Копия» и оригинал делили одну стратегию. Два кубика,
  которые выглядят независимыми, расходовали один генератор: у кубика с `SeededRandomStrategy`
  броски копии сдвигали последовательность оригинала, и воспроизводимость ломалась далеко от причины.
* **Fail fast, fail loud.** Ошибка не исчезала, а превращалась в тихий логический баг.
  `except Exception` к тому же ловил всё подряд, включая ошибки в коде самой стратегии.

## Решение

Принято решение поднимать доменное исключение **`DiceCopyError`**, если стратегию нельзя скопировать,
потому что метод, который не может выполнить свой контракт, должен сообщить об этом, а не подменить результат.

### Детали реализации

1. `DiceCopyError` наследует `TypeError`: `deepcopy` несовместимого объекта сам обычно бросает
   `TypeError`, поэтому код, который его уже ловит, продолжит работать.
2. Исходная ошибка сохраняется через `raise ... from error` и доступна в `__cause__`.
3. Текст ошибки называет кубик, который не удалось скопировать.
4. `try` охватывает только копирование стратегий; `replace(...)` вынесен из него, чтобы не перехватывать
   посторонние ошибки.

```python
try:
    new_random_strategy = deepcopy(self._randomization_strategy, memo)
    new_roll_strategy = deepcopy(self._roll_strategy, memo)
except Exception as error:
    raise DiceCopyError(f"Cannot deep-copy the strategies of {self!r}: {error}") from error
return replace(self, _randomization_strategy=new_random_strategy, _roll_strategy=new_roll_strategy)
```

## Альтернативы

* **Оставить тихий возврат `self`:**
  * *Плюсы:* `deepcopy` никогда не падает.
  * *Минусы:* нарушает контракт, POLS и fail loud; «копия» делит состояние с оригиналом.

* **Убрать `try` и пробросить исходную ошибку:**
  * *Плюсы:* тоже fail loud, проще кода.
  * *Минусы:* пользователь получает разнородные исключения из чужого кода стратегии, без указания,
    какой кубик виноват, и без одной точки для `except`.

## Последствия

### Положительные

* [+] Стратегия, которую нельзя скопировать (блокировка, открытый ресурс), заметна сразу при `deepcopy`,
  а не через странные броски позже.
* [+] Одна точка для `except DiceCopyError` и понятный контекст в сообщении.
* [+] Поведение покрыто регрессионными тестами в `tests/test_operators.py`: копия независима,
  а ошибка копирования поднимает `DiceCopyError` с исходной причиной.

### Отрицательные

* [-] Появилось новое публичное исключение `dicing.DiceCopyError`, которое нужно поддерживать.
* [-] Код, который полагался на тихий возврат `self`, теперь получит исключение
  (на практике это был скрытый баг).
